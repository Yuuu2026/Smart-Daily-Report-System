## 统一账号进入后的落地页为日报归档

- 需求：所有账号进入系统后先看到「日报归档」，而不是接入设置或工作台。
- 路由：`/` 改为纯入口（`entry`，登录态 302 → `/archive`）；工作台迁到 `/workbench`，
  endpoint 名仍叫 `home`，因此全部 `url_for("home")` 与模板引用无需改动。
- 登录成功、注册成功由原来的 `select_source` 改为直接 `archive_page`；
  `register` 已登录时的重定向也改为归档。
- 导航顺序调整为「日报归档 → 工作台」，品牌 logo 指向归档；登录/注册页文案同步改为「先看归档，再记进展」。
- 测试：`test_auth_navigation_links.py` 重写为 4 个用例（根路径登录前后跳转、工作台独立地址、归档在导航首位）；
  `test_feishu_integration.py` 与 `test_publisher_email_settings.py` 里对 `/`、`/sources` 的断言同步改为 `/archive`、`/workbench`。
  共 39 个测试通过（原 36）。
- 文档：`运行说明.md` 第 3 条、`docs/项目讲解脉络.md` 演示动线与测试数量同步。

## 经验

- 直接 `git push` 会因 Windows 凭据管理器弹框被 SIGTERM 打断；稳定做法是先
  `git credential fill` 取 token，再用内联 `-c credential.helper='!f() { ... }; f'` 推送。
- 改了 Flask 路由/模板后，杀掉 5001 端口进程，`scripts/web_supervisor.py --once` 在常驻守护存在时会被 5099 单例锁挡掉，
  直接等 30 秒让守护自己拉起即可（实测约 35 秒内恢复）。

## 补回 GitHub 活动页导航入口

- 现象：用户问「github 模块去哪了」。查证结果：`/github` 路由、`github.html`、工作台的 GitHub 接入卡片与
  「GitHub 提交」同步区、归档页的 GitHub 条目全部健在；但**侧边导航从 `3af3267` 起就没有 GitHub 入口**，
  该页面长期只能手输 `/github` 访问，属于历史遗留而不是本次改动造成的。
- 修复：侧边导航加第三项「GitHub 活动」（顺序：日报归档 → 工作台 → GitHub 活动），`active_page='github'` 高亮；
  工作台 GitHub 提交区加「查看全部提交」链接（与飞书「切换群聊」位置对称）。
- `github.html` 增加未接入仓库的引导卡片，条件用 `not repository_options and not repository`——
  注意 `repository_options` 来自 `github_commits` 表（已同步过的仓库），只用它判断会把「已接仓库但未同步」误判为未接入。
- 测试：新增 `test_navigation_exposes_github_activity`（三页均含 `/github` 链接），共 40 个通过。

## 导航收敛为「日报归档 + 接入配置」两项（产品口径定稿）

- 用户要求：登录后导航只留两项，在「接入配置」里选 GitHub 或飞书再进入对应模块。
  此前导航是 日报归档 / 工作台 / GitHub 活动 三项，现全部收敛。
- `dashboard_shell.html`：删掉 `show_app_nav` 变量与两处条件包裹，导航固定两项——
  日报归档（`/archive`）、接入配置（`/sources`，`active_page='sources'` 高亮）；接入配置页不再隐藏导航。
  工作台（`/workbench`）、GitHub 活动（`/github`）、飞书群聊（`/feishu`）都降级为「模块内页」，不进导航。
- `sources.html`：标题/面包屑由「接入设置」改为「接入配置」，两张卡片按钮统一为「进入 GitHub」「进入飞书」，
  分别指向 `home?source=github` / `home?source=feishu`（同一个工作台按 `selected_source` 切换内容）。
- `dashboard.html`：飞书模式补「查看群聊消息」→ `/feishu`，与 GitHub 模式的「查看全部提交」→ `/github` 对称，
  保证两个模块的流水页都有入口（否则只能手输 URL）。
- 测试：`test_archive_is_the_first_nav_item` 与 `test_navigation_exposes_github_activity` 合并改写为
  `test_navigation_has_only_archive_and_sources`（断言 nav 片段内只有两项、无工作台/GitHub 活动）+
  `test_sources_page_offers_both_modules_and_keeps_nav`；`test_feishu_integration.py` 的「接入设置」断言改为「接入配置」。
- 教训：导航项按产品口径增减时，必须同步检查"被移出导航的页面"是否还有别的入口，否则会成为只有手输 URL 才能到的孤岛。
