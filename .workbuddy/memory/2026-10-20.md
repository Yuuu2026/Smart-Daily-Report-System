## 接通 CD（持续部署到本机）
- 用户诉求："为我接通CD"。给出三个方向（部署到本机 / 云服务器 / 仅发布产物），用户选择**自动部署到本机**。
- 实施：GitHub Actions 自托管 runner（仓库内注册，名称 Lenovo-Desktop，标签 self-hosted,windows,x64,local-deploy）。
  - 下载 runner v2.338.0（99MB，经 127.0.0.1:7897 代理），`config.cmd --unattended` 注册。
  - 无管理员权限 → 装不了 Windows 服务，改用计划任务 `GitHubActionsRunner`（登录自启）拉起 `run.cmd`。
  - `C:\Users\Lenovo\actions-runner\.env` 写入 HTTPS_PROXY/HTTP_PROXY/NO_PROXY，否则 runner 连不上 GitHub。
- 部署工程化：
  - 新增 `.github/workflows/deploy.yml`：`workflow_run`（CI 完成后）+ `workflow_dispatch` 手动触发；
    步骤 = 拉取代码（fetch + merge --ff-only）→ 装依赖 → 重启 → 健康检查（5000/archive、5001/login 需 200）→ 汇总。
  - 关键设计：不 checkout runner 工作区，直接在项目目录部署；用 junction `C:\Users\Lenovo\dailyreport` 规避中文路径编码。
  - 关键设计：网站由计划任务 `DailyReportWeb` 常驻（`scripts/run_web.cmd`），部署时用 `schtasks /End` + `/Run` 重启，
    避免 runner 在 job 结束时清理子进程把网站杀掉。
  - `start_web.py` 新增 `START_WEB_NO_BROWSER` 开关，避免每次部署弹浏览器。
- 验证：
  1. 首次 push（ed1d889）→ CI success → Deploy success，6 步全绿，耗时 37s，端口 PID 变化证明重启生效。
  2. 通过 API 从"远端"提交 3ff4023（新增 `.github/CD.md`）→ CI → Deploy 自动把该提交 merge 到本机，
     本机 HEAD 变为 3ff4023 且文件已落地，再次重启后两站仍 200。→ 真实 CD 闭环。
- 坑：`schtasks.exe` 在当前 agent 沙箱被安全策略禁止（Program Blacklist），查询任务状态需改用 PowerShell `Get-ScheduledTask`；
  不影响部署本身，因为部署步骤在 runner 进程下执行。
