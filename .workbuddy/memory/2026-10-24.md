## 命令行日报：不走网页直接发（本次完成）

用户要把「发布日报」从网页搬到终端：每次 git 提交后自动从提示词生成今日完成总结，
问一句收件邮箱与飞书，确认后直接发送。

### 新增文件
- `web/session_prompts.py`：从 `~/.workbuddy/projects/<slug>` 与 `~/.claude/projects/<slug>`
  的 jsonl 里按天提取用户提示词。剥离 system-reminder、工具结果、fenced code、
  压缩摘要（`conversation_history_summary` 等标记），去重后按时间升序。
  slug 规则：WorkBuddy 保留中文、Claude Code 把非字母数字全换成 `-`。
- `web/daily_summary.py`：`collect_signals` 拿齐提交/本地改动/提示词/飞书，
  `build_report` 生成 solved/finished/problems/next_steps/summary/tags/warnings。
- `scripts/report_cli.py`：终端入口，打印草稿 → 问收件人 → 写 `published_items` → 发信 →
  写 `email_delivery_logs`。参数：`--dry-run/--yes/--date/--user/--to/--hours/--solved/--attach/
  --no-feishu/--sync-feishu/--install-hook/--uninstall-hook`。
- `scripts/git-hooks/post-commit`：`[ -t 0 ]` 判定交互终端，非交互自动跳过（IDE/CI 不会卡）；
  回答 `a` 写 `.git/daily-report-hook.off` 关闭询问；`DAILY_REPORT_SKIP=1` 临时跳过。

### 口径（重要）
- **完成项只来自 git 提交**，每条对应一个 commit；`记忆：`/`docs:`/`test:` 类提交排在后面，
  内部记忆提交不进正文。
- 提示词只用于总述、标签、下一步计划与问题项，不直接当完成项——避免把「想做」说成「做完了」。
- 当天有改动但没提交：措辞是「调整（未提交，+x / −y）」，并在 warnings 里说明。
- 修好类提交（`fix:` 或「修复/解决」开头）进 solved，其余进 finished。
- 没有数据来源就留空，不写占位句。

### 踩坑
- 噪音判定最初用 `raw.count("\n") > 25`，结果把正常需求也过滤了：一条用户消息里
  system-reminder 就有 200 多行。改成用**清洗后**的长度判断（> 600 字才算粘贴日志）。
- `clean_text` 原本只折叠连续空行，单换行留着；改成全部折叠成空格，句子更干净。
- `MIN_TEXT` 从 6 降到 4，「补一个测试」这种 5 字需求才不会被丢掉。

## 配置集中到 scripts/report_config.py（10:05）

用户问「在哪可以手动配置、不通过一 AI 发送日报」，先答了网页/CLI，被纠正为
**要在代码文件的某个文件中配置**。于是新增 `scripts/report_config.py`：

- 常量：`USER` / `RECIPIENTS` / `HOURS` / `REPORT_DETAIL` /
  `SMTP_HOST,PORT,USERNAME,PASSWORD,SECURE` / `INCLUDE_FEISHU` / `SYNC_FEISHU` / `AUTO_SEND`
- `report_cli.load_config()` 用 `exec` 读它（不是 importlib，方便测试传临时路径）；
  文件缺失、语法错、字段非法都回落 `CONFIG_DEFAULTS`，绝不中断发送
- 优先级：**命令行参数 > 配置文件 > 数据库/`.smtp.local.json`**
- `SMTP_*` 五项全空时仍走 `smtp_settings_from_env()`；填了 `SMTP_HOST` 才完全接管发信
- `AUTO_SEND=True` 等价 `--yes`：打印草稿后直接发；`INCLUDE_FEISHU=False` 等价 `--no-feishu`
- `save_item` / `deliver` 新增 `report_detail` 参数（此前硬编码「标准」）
- 测试 126 → 136（`ConfigFileTests` 6 个 + `SmtpConfigTests` 4 个）

**注意**：`SMTP_PASSWORD` 明文写在公开仓库里等于泄露授权码，注释已警告；
默认留空走 `.smtp.local.json`。

## 发送入口改名 + 交互压成一步（10:20）

用户反馈「发送的方法还是太麻烦了，改一个显眼的名字，同时简化方法」。

- 根目录新增 **`发送日报.bat`**（CRLF + UTF-8，`chcp 65001`）：双击即跑
  `scripts\report_cli.py`；复用 `启动网站.bat` 的 `:try_python` 思路，只接受
  「Python 3 且能 import flask」的解释器；**无参数时结束 `pause`**（双击能看结果），
  带参数运行不暂停（方便脚本调用）。窗口标题「发送今日日报」。
- 交互从三步压成一步：新增 `ask_send_target(recipients)` ——
  回车=发到默认地址、输入邮箱=改发、输入 `n/取消/不发` = 取消。飞书不再逐次询问，
  统一由 `report_config.INCLUDE_FEISHU` 决定。
- **顺手修了个旧 bug**：`normalize_recipients` 是变参函数，之前 `--to a@x.com,b@y.com`
  与交互输入多个邮箱都会抛「格式不正确」。新增 `parse_recipients()` 按
  `, ， ; ； 空格` 拆分再交给 `normalize_recipients(*parts)`；`--to` 与交互都改用它。
- `.gitattributes` 追加 `*.bat text eol=crlf`。
- 测试 134 → 142（`SendTargetTests` 4 个 + `RecipientParsingTests` 4 个）。

**推送方式变更**：`https://user:$TOKEN@github.com/...` 这种 URL 内嵌凭据现在被 GitHub
拒绝（`Invalid username or token`），同一 token 打 API 仍是 200。改用 Basic 头：
```
AUTH=$(printf "Yuuu2026:%s" "$TOKEN" | base64 -w0)
git -c credential.helper="" -c http.https://github.com.proxy=http://127.0.0.1:7897 \
    -c http.extraHeader="Authorization: Basic $AUTH" push https://github.com/... master
```
