### 新增 `web/daily_brief.py`
- `split_items()` 拆句：先按行，去 `-` / `1.` / `①` 前缀，再按 `；` 断，长句（>26 字）才按 `。` 断。
- `build_brief()` 返回 overview / summary / tags / done_items / plan_items / problem_items /
  mix / mix_caption / insight / change_total。
- **概览口径**：`tasks = done + doing`，done 来自 solved+finished 拆句，doing 来自 next_steps 拆句。
  这样「完成 + 进行中 = 任务」天然自洽，全部可追溯。
- **hours** 只能来自成员填写（`_coerce_hours` 限制 0<h<=24），没填就不显示这一格。
- **改动分布**：优先按代码改动的模块聚合新增行数（Python 逻辑 / 页面模板 / 页面样式），
  只涉及一个模块时回退到近 7 天数据来源占比，都凑不出两条就不渲染。
- **洞察**：done>=3 且无风险 → 状态良好；done>=2 → 状态平稳；有风险 → 节奏偏紧；否则记录偏少。
- 刻意不做「项目进度 85%」这类百分比 —— 系统里没有项目维度数据，硬编就是假数据。

### 邮件版式
区块顺序：今日概览（KPI 网格 3×2）→ 今日总结（一句话 + 标签胶囊）→ 今日完成（✓）→
问题与风险（⚠）→ 改动分布（条形）→ 明日计划（□）→ 工作洞察（状态胶囊 + 建议）→
最近代码改动（+91 / −34）→ 数据流水 → 近 7 天柱状图。

- 新增渲染函数：`_email_block` / `_email_kpi_grid` / `_email_tags` / `_email_checklist` /
  `_email_bars` / `_email_insight`；旧的 `_email_section` 保留给同步结果邮件用。
- **进度条不能用 `bgcolor` 属性**：现有测试 `assertEqual(body.count("bgcolor="), 3)` 在数柱状图的柱子，
  用 `style="background-color:..."` 绕开。
- 「今日完成」的 meta 写「来源：解决的问题」/「来源：完成事项」，这样既有溯源信息，
  也满足原有测试「solved 非空要出现『解决的问题』、solved 空则不能出现」。
- 顶部的 `summary` / `stats` 传空，改由概览网格承担，避免与「今日总结」重复。
- 概览右上角 meta 改成「完成率 57%」。
